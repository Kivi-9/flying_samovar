# Ревью ТЗ «Пар-Облако»

## 1. Неясно, как сравнивать дробный расход с остатком энергии

В `SPEC.md` (§3.0, п. 5 и §3.4.2) указан допуск `1e-9` для вещественных результатов, а перелёт разрешён, если энергии хватает ровно. Если начать с 11 единиц, взлететь и пролететь `0.9` км с попутным ветром, при обычном вычитании `float` останется `0.09999999999999998`. При строгом сравнении следующий перелёт на `0.1` км отклонится, хотя по расчёту энергии хватает.

Стоит уточнить, применяется ли допуск к проверке запаса, и зафиксировать, должен ли второй перелёт в этом примере пройти с остатком `0.0` или завершиться `SamovarNoEnergy`.

## 2. В TC-15 не проверен порядок валидации `calculate_energy`

По `SPEC.md` (§3.0, п. 3 и §3.4.5) сначала проверяются типы обоих аргументов, потом их значения. В TC-15 есть `calculate_energy("10", "hurricane")`, но даже при проверке каждого аргумента целиком по очереди этот вызов даст нужный `TypeError`.

Предлагаю добавить `calculate_energy(0, 5)`: ожидается `TypeError` из-за типа погоды, а не `ValueError` из-за нулевой дистанции. Состояние должно остаться прежним. Для `fly` такой случай уже есть в TC-11.

## 3. В TC-08 тест проверяет время строже, чем требует ТЗ

В `SPEC.md` (§3.0, п. 5) и `TEST_CASES.md` указан допуск `1e-9`, но в `tests/test_flying_samovar.py` время сравнивается через `assertAlmostEqual(..., places=9)`. Например, при ожидаемом времени `0.5` ч результат `0.50000000075` укладывается в допуск, но тест его не примет: `places` округляет разницу, а не сравнивает её напрямую с допуском.

Чтобы тест проверял именно допуск из ТЗ, предлагаю использовать `assertAlmostEqual(..., delta=1e-9)` там, где сравниваются вещественные результаты с этим допуском.
